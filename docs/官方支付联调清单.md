# 官方支付联调清单（微信支付 + 支付宝直连）

> 2026-09-06 拍板：放弃虎皮椒聚合通道，改接官方直连。本文档面向商户号到手后的联调：每个 env 怎么填、平台上要开哪些产品权限、回调地址怎么配、验签排错怎么做。密钥未配置期间，支付端点自动 503 降级（`payment_not_configured`），其余功能不受影响。

## 一、环境变量（.env / 部署机环境）

### 微信支付（APIv3 · Native 扫码）

| env | 说明 | 从哪里拿 |
| --- | --- | --- |
| `WECHAT_APPID` | 公众号/服务号/小程序 AppID（需与商户号绑定） | 微信公众平台「设置与开发 → 基本配置」 |
| `WECHAT_MCHID` | 商户号 | 微信商户平台（pay.weixin.qq.com）「账户中心 → 商户信息」 |
| `WECHAT_APIV3_KEY` | APIv3 密钥（32 位） | 商户平台「账户中心 → API 安全 → 设置 APIv3 密钥」 |
| `WECHAT_MCH_PRIVATE_KEY_PATH` | 商户 API 私钥文件路径（`apiclient_key.pem`） | 商户平台「API 安全 → 申请 API 证书」后下载，**不要提交进仓库** |
| `WECHAT_MCH_CERT_SERIAL` | 商户证书序列号（40 位十六进制） | 同上证书详情页；或 `openssl x509 -in apiclient_cert.pem -serial -noout` |

### 支付宝（电脑/手机网站支付）

| env | 说明 | 从哪里拿 |
| --- | --- | --- |
| `ALIPAY_APPID` | 应用 AppID | 支付宝开放平台（open.alipay.com）「控制台 → 应用列表」 |
| `ALIPAY_PRIVATE_KEY_PATH` | 应用私钥文件路径（PKCS#8 PEM 或纯 base64 主体均可） | 密钥工具生成后，在开放平台「应用 → 开发设置 → 接口加签方式」配置 |
| `ALIPAY_PUBLIC_KEY_PATH` | 支付宝公钥文件路径（同样兼容纯 base64） | 配置完应用公钥后，开放平台会给出「支付宝公钥」，**用它**（不是应用公钥） |
| `ALIPAY_GATEWAY`（可选） | 网关地址；缺省走正式环境 `https://openapi.alipay.com/gateway.do`；沙箱填 `https://openapi-sandbox.dl.alipaydev.com/gateway.do` | 开放平台沙箱页 |

### 回调与通用

| env | 说明 |
| --- | --- |
| `PAYMENT_NOTIFY_URL` | 回调基址，须为 **HTTPS 公网域名**，例如 `https://yourdomain.com`。后端会拼出 `/api/payment/notify/wechat`、`/api/payment/notify/alipay` 下发 |
| `WECHAT_NOTIFY_URL` / `ALIPAY_NOTIFY_URL` | 可选，逐渠道覆盖完整回调地址（一般不用） |
| `PAYMENT_ORDER_TTL_MINUTES` | 可选，订单保留时长（默认 15 分钟） |

> 个体工商户执照下来 → 域名备案（ICP）→ HTTPS 证书 → 才能配回调。**回调地址在域名/ICP 落定前保持占位**，期间下单会因 `is_channel_configured` 判定 notify_url 缺失而维持 503 降级——这是预期行为。

## 二、平台侧要开通的产品权限

### 微信商户平台
1. 「产品中心 → Native 支付」开通（网站扫码场景）。
2. 「账户中心 → API 安全」：设置 APIv3 密钥、申请 API 证书（拿私钥 + 序列号）。
3. 「产品中心 → 开发配置」：**支付授权目录**填收银台页（如 `https://yourdomain.com/`）；Native 回调无需在此配置，代码里由统一下单的 `notify_url` 带上。

### 支付宝开放平台
1. 控制台创建「网页/移动应用」，签约「电脑网站支付」+「手机网站支付」。
2. 开发设置 → 接口加签方式选 **公钥模式（RSA2）**，配置应用公钥、记下支付宝公钥。
3. 应用上线（审核通过）后才能用正式网关收款；沙箱环境可先联调（沙箱账号在「研发服务 → 沙箱」申请，需要支付宝账号，**本仓库未做沙箱实测，联调时按本清单走一遍即可**）。

## 三、联调步骤

1. 后端 `.env` 填好两组密钥 → 重启 → `GET /api/subscription/plans` 应返回 `channels: {"wechat": true, "alipay": true}`（逐渠道亮灯即配置生效）。
2. 前端收银台选档 → 渠道面板两个按钮可点：
   - **微信**：展示本地渲染的二维码（后端 `code_url` → 前端 SVG），微信扫码 → 支付 → 回调入账；
   - **支付宝**：点「打开支付宝收银台」跳官方页面付款。
3. 支付后观察后端日志：`payment notify`（wechat/alipay）应出现 `confirmed`；前端 3 秒轮询自动刷新状态卡。
4. 主动关单：收银台「取消支付」；超时：TTL 到点自动关单 + 网关 best-effort 关单。
5. 对账兜底：挂起订单重启后 `reconcile_pending_orders` 会按渠道查询补单（未配置渠道跳过）。

## 四、验签排错

| 症状 | 排查 |
| --- | --- |
| 微信回调日志 `rejected: bad signature` | ① APIv3 密钥是否与商户平台一致（解密失败也走这里）；② 平台证书缓存是否过期（自动 12h 刷新，可重启强制拉取）；③ 回调 body 是否被网关/代理改写（必须透传原始字节） |
| 微信回调 `unknown platform serial` | 平台证书轮换后缓存未更新，看 `/v3/certificates` 拉取日志；确认服务器能访问 `api.mch.weixin.qq.com` |
| 支付宝回调应答 `fail` | 「支付宝公钥」配成了「应用公钥」（最常见）；或参与签名参数集不对——后端按「除 sign/sign_type 外的公共参数 + biz_content」拼串，未知字段会原样参与验签 |
| 支付宝回调查询参数被截断 | notify URL 走了 form 解析，确认代理没改 Content-Type；后端已做整包验签，日志里能看到原始报文留档（`payment_callbacks` 表） |
| 下单 502 `GATEWAY_ERROR` | 商户号权限未开通 / 应用未上线 / 网关不通；错误信息里带渠道原始 code |
| 下单 503 `payment_not_configured` | env 缺失或密钥文件路径不存在或 notify_url 未配（见上文降级说明） |

> 所有回调（含验签失败、金额不符、处理异常）都会原文落档 `payment_callbacks`，排错先查这张表。

## 五、金额与口径约定

- 本地与订单一律记「分」；微信 `amount.total` 原样；支付宝 `total_amount`（元）×100 后比对。
- 回调金额与订单不符 → 不入账，应答失败让渠道重试，落档 `amount_mismatch`。
